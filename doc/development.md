# 构建、发布与开发（Rust 版）

## 构建

需要 Rust 工具链（<https://rustup.rs>）。

```bash
cd auto-asmr
```

```bash
cargo build --release
```

生成的程序在 `target/release/auto-asmr`（Windows 是 `auto-asmr.exe`）。HRIR、房间、耳机补偿数据都内嵌在程序里，单个文件即可运行，约 25 MB。

| 系统 | 说明 |
|---|---|
| Windows | 直接双击 `auto-asmr.exe`。直播时把输出设备选成虚拟声卡（如 VB-Cable）。 |
| macOS | 运行 `tools/bundle_macos.sh` 生成 `target/release/auto-asmr.app`，双击启动。打包后 macOS 才会弹出麦克风授权。 |
| Linux | 编译前需要 ALSA 开发库（Debian / Ubuntu：`sudo apt install libasound2-dev`）。 |

## GitHub 自动构建与发布

推送任意名称的 tag 都会触发 `.github/workflows/release.yml`，并行跑四个构建任务：用 Rust 1.95.0 测试和构建 Windows x64、Linux x64 发布版（验证程序启动）；用 Rust 最新稳定版测试和构建安卓 APK、浏览器插件（这两部分是在最新稳定版上开发的）。全部成功后自动创建或更新该 tag 对应的 GitHub Release。附件包含 `auto-asmr.exe`、`auto-asmr-windows-x64.zip`、`auto-asmr-linux-x64.tar.gz`、`auto-asmr-android.apk`、`auto-asmr-chromium.zip` 和统一的 `SHA256SUMS.txt`；压缩包内含说明文档，Actions 页面也可下载构建产物。APK 的签名密钥放在仓库的 Secrets 里，做法见[安卓版 · 发布](android-dev.md#发布)；没配时 APK 用临时密钥签名，不能覆盖安装之前的版本。插件任务跑插件的 Rust 测试，tag 是数字版本（`v1.2.3`）时把版本号写进 `manifest.json`，用 `build.sh --zip` 打包，再检查包里有 wasm 和 manifest 引用到的页面、图标；浏览器里的测试和端到端测试要真浏览器，没放进 CI。

Linux 版在 Ubuntu 22.04 上构建（GNU/glibc），解压后运行 `./auto-asmr`，需要桌面图形环境以及 ALSA 等运行库；打包保留程序的可执行权限。

```bash
git tag v0.1.0
git push origin v0.1.0
```

工作流文件需要先提交并推送，且包含在该 tag 指向的提交中。本地创建 tag 后，需要推送到 GitHub 才会触发构建。

## 代码结构

本包分成库和程序两部分：库（`src/lib.rs`）是信号处理 `dsp` 和设置文件格式 `config`，安卓版（`auto-asmr-android/rust`，打开 `external-data`：数据文件不编进库，运行时由 `dsp::data::provide` 提供）和浏览器插件（`auto-asmr-chromium/wasm`，见[浏览器插件](chromium.md)）也依赖它；程序（`src/main.rs`）是桌面版的界面和命令行，音频设备、界面、解码这些依赖都在默认开启的 `desktop` feature 里。只编译库（不带桌面依赖）：

```bash
cargo build --release --lib --no-default-features
```

| 路径 | 内容 |
|---|---|
| `src/lib.rs` | 库的入口，导出 `dsp` 和 `config` |
| `src/config.rs` | 设置文件：关闭时自动保存、「导出 / 导入配置」用的 `Saved` 和读写函数（键值表 `{"app": …}`）。安卓版和浏览器插件读写同一个格式，所以配置文件几边通用 |
| `src/dsp/testsig.rs` | 合成的测试信号（人声、刮擦声、歌）和积分响度，库和程序的测试、性能测试共用 |
| `src/dsp/` | 信号处理：数据表、直达声渲染、房间、运动、语音分析、人声处理、响度与限制器、引擎；`mix.rs` 是多音频合成（每个音源一个引擎、位置、响度对齐、相加；左右双人是同一个音频当两个音源、第 2 个晚一点；`LiveMix` 是边播边处理的左右双人：一路输入留一小段历史，第 2 个声音从里面晚一点取，安卓版和浏览器插件处理网页声音用它）；`align.rs` 是合成前的自动对齐（色度 / 频带粗找、起音包络细找、波形逐样本）；`balance.rs` 是合成的自动平衡（短时响度 + 位置增益，往平均拉；主播模式的左右双人边听边算输入响度）；`rain.rs` 是背景音（实时生成的雨声：雨滴谱、撞击脉冲卷 HRIR、流动（8D 环绕的重心）、落地声、屋檐滴水、隔窗、按期望功率定响度），`thunder.rs` 是可选的雷声（曲折闪电通道上的 N 波、空气吸收、天上各方向的 HRIR、回声） |
| `src/realtime.rs` | 设备枚举、输入输出流、时钟漂移补偿；主播模式的左右双人（麦克风输入记进一小段环形历史，第 2 个声音从里面晚一点取，交给 `mix.rs` 的合成器） |
| `src/offline.rs` | 文件解码、两遍处理、写 WAV |
| `src/gui.rs` | 界面 |
| `assets/ku100.bin` | 内嵌数据（10.9 MB） |
| `tools/export_assets.py` | 从 Python 版的预处理结果重新导出 `assets/ku100.bin` |
| `tools/bundle_macos.sh` | 打包 macOS 应用 |

重新导出数据（一般不需要）：

```bash
uv run tools/export_assets.py
```
